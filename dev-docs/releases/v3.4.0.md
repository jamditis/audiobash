# AudioBash v3.4.0 release evidence

Status: Work in progress.

This document records the evidence used to prepare AudioBash v3.4.0. It does not contain passwords, private keys, API key identifiers, issuer identifiers, or certificate archives.

## Release goal

Ship smaller and more stable macOS arm64 and x64 packages. Both packages must use a supported Electron release, pass the test and static-analysis gates, carry a Developer ID signature with a secure timestamp, pass Apple notarization, include a stapled ticket, and pass Gatekeeper checks before publication.

## Task 5 VAD startup deferral evidence

The renderer now imports VAD and ONNX only when the user starts VAD or continuous recording mode. The runtime model is pinned to `legacy`. The generated `public/vad` directory is recreated on each build and contains only the legacy model, the audio worklet, and the two ONNX WebAssembly runtime files. The unused 2,327,524-byte V5 model is not copied or packaged.

The hook uses one cached module load, one active or pending start, one serialized cleanup queue, and a generation number for stale callbacks. It handles React StrictMode, simultaneous start calls, stop during module loading, stop during the library's internal `startOnLoad` work, immediate restart, unmount, late instances, permission errors, module-load retry, and stale callbacks from a prior session. The library starts inside `MicVAD.new()` when `startOnLoad` is true, so a late instance can start before the factory resolves. The hook disposes that instance as soon as it becomes available.

The bundle inspector uses UTF-8 byte counts and walks Rollup's static and dynamic chunk graph. The initial entry has no VAD or ONNX modules, every VAD owner is reachable through the dynamic graph, and `index.html` does not preload a VAD chunk.
