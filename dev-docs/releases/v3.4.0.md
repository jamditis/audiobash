# AudioBash v3.4.0 release evidence

Status: Work in progress.

This document records the evidence used to prepare AudioBash v3.4.0. It does not contain passwords, private keys, API key identifiers, issuer identifiers, or certificate archives.

## Release goal

Ship smaller and more stable macOS arm64 and x64 packages. Both packages must use a supported Electron release, pass the test and static-analysis gates, carry a Developer ID signature with a secure timestamp, pass Apple notarization, include a stapled ticket, and pass Gatekeeper checks before publication.

## Task 4 package pruning evidence

Renderer-only libraries now remain available to Vite and tests as development dependencies. Electron-builder no longer installs React, Xterm, VAD, or ONNX packages into the production dependency closure. The mac package also excludes five installed dependency trees that its runtime does not use: `node-addon-api`, `json-schema-to-ts`, `ts-algebra`, `@babel/runtime`, and `@remotion/captions`. These packages remain in the lock file for source installation. The package keeps the main-process SDKs and target `node-pty` runtime.

The first macOS exclusion build produced a 4.0 GB app. Later inspection of electron-builder 26 showed that global and platform file patterns are combined, so replacement of the global list is not a proven root cause. The macOS file list remains self-contained and has three positive application patterns, which prevents an all-negative list from selecting the full project if the global list changes. A second red package test found that automatic native-module unpacking copied 17 node-pty files outside the arm64 archive. Automatic unpacking is disabled only for macOS, and the explicit macOS rule unpacks only the target `pty.node` and `spawn-helper`. Windows and Linux retain electron-builder's native-module detection.

The two-architecture package gate passes 30 tests. Each package contains only its target PTY binaries, keeps node-pty runtime JavaScript in `app.asar`, keeps the four renderer sounds and both Task 4 VAD models, and omits retired remote-control files, duplicate external sounds, and the five non-runtime dependency trees. The package policy also rejects every prebuild entry outside the exact target architecture directory, regardless of file extension. Dependency probes run from an empty temporary home and working directory with a small allowlist of inherited locale, path, and temporary-directory variables. They clear Node search and option variables and reject every non-built-in CommonJS module resolution outside `app.asar` or `app.asar.unpacked`. The probes load each unbundled main-process dependency from the packaged ASAR, call the Anthropic JSON-schema helper, and call both Whisper caption conversion functions with a known non-empty caption fixture. A cold x64 probe took 34 seconds under Rosetta, so the test gives the child process a 60-second bound and Vitest a 70-second bound. Strict signature checks pass for each app, `pty.node`, and `spawn-helper`. Packaged arm64 and x64 PTY probes both start zsh and exit successfully. The x64 probes ran under Rosetta 2 on Apple Silicon; native Intel testing remains a final release gate. Isolated startup probes keep each app alive, create a non-empty tray image, load node-pty, start the initial shell, and remove that shell during app shutdown.

The Task 4 sample builds skipped notarization because the current hook reads Apple ID variables and does not consume the approved App Store Connect API key. Task 11 must add API-key support and make release notarization fail closed. These samples are package-content controls, not release trust passes. Live sound playback, tray clicks and menu actions, microphone voice capture, and live VAD behavior remain manual gates. An earlier arm64 startup probe logged repeated Electron menu-model warnings after tray creation. The warning did not appear in the final short arm64 or x64 startup probes, but the supported Electron update and a longer tray interaction test must confirm that result before release acceptance.
